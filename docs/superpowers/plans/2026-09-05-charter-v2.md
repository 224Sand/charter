# Charter v2 Implementation Plan

**Goal:** Replace v1's inert `no_self_signoff` with a gate that fires on a fact the caller cannot forge — the server's own connection id — while keeping a review pass cheap enough that people actually run the two-session flow.

**Spec:** [v2 design](../specs/2026-09-05-charter-v2-independent-review-design.md). Decision #1 locked: a missing second session **blocks**.

**Why this plan is shorter than v1's.** The v1 plan carried complete code in every step because each task was briefed to a subagent with zero context. This one is executed inline with full context, so it records task boundaries, interfaces, and what each test must be able to detect — not transcription. The discipline that matters is unchanged: test first, and every guard must fail when removed.

## Global Constraints

- Python `>=3.11`. Package `charter`. Import root `src/charter/`.
- **Every guard has a test that fails when the guard is removed.** Verified by reverting it.
- The build record stays append-only. Timestamps UTC.
- **Backward compatibility is a correctness rule, not a courtesy:** a v1 sign-off has no `connection_id`. It must load, and it must report the independence check as *unavailable* — never as *passed*. An old record silently satisfying a new gate is this project's own failure mode.
- `next()` payload carries no file contents and stays under **8 KB** for the fixture build.
- Run tests with `uv run pytest`. 98 tests currently pass; none may regress.

---

### Task 1 — Connection identity on the server

**Files:** `src/charter/mcp_server.py`, `src/charter/loop/machine.py`, `tests/test_mcp_server.py`

`Handlers.__init__` generates `self.connection_id = uuid4().hex` and passes it to `Council`. `Council.__init__(store, repo, connection_id)`.

**Tests must detect:** two `Handlers` instances get different ids (a constant would fail); the id is reachable by no tool argument — `charter_submit`'s input schema has no field that sets it, and passing one is rejected as an invalid argument.

---

### Task 2 — Record the identity, keep v1 records readable

**Files:** `src/charter/record/models.py`, `tests/test_record_store.py`

`Signoff` gains `connection_id: str | None = None`. `producer_role` becomes `str | None = None` (retained so v1 rows parse; no longer consulted).

**Tests must detect:** a v1-shaped row — `role`, `producer_role`, `artifact`, `tree_sha`, no `connection_id` — still loads, and its `connection_id` is `None`. A round-trip preserves a real id.

---

### Task 3 — The gate

**Files:** `src/charter/gates/checks.py`, `tests/test_gates.py`

`no_self_signoff(signoff, signoffs, roster)` → `GateResult`. Finds the developer's sign-off on `signoff.tree_sha` and:

- developer's id missing, or this sign-off's id missing → **block**, reason names it as *unavailable*, not failed
- ids equal → **block**, "same process produced and reviewed this"
- ids differ → allow
- no developer sign-off yet on this tree → allow (nothing to be independent of; the developer's own pass is the baseline, per design §11 #3)

**Tests must detect:** each of those four branches, and specifically that a v1 row reports *unavailable* rather than passing — delete the missing-id branch and that test must fail.

---

### Task 4 — Wire it into the loop

**Files:** `src/charter/loop/machine.py`, `tests/test_loop.py`

Delete `_producer_for`. Stamp `connection_id=self.connection_id` on the `Signoff`. Call the new gate with the full sign-off list and roster, before `append_signoff` — the ordering v1's review already established.

**Tests must detect:** a reviewer submitting from the same `Council` (same id) as the developer is refused and the sign-off is **not** appended; two `Council`s with different ids on the same store complete the sequence.

---

### Task 5 — Bounded handover

**Files:** `src/charter/loop/machine.py`, `tests/test_loop.py`

`next()`'s assignment carries role brief, contract, artifact under review, cited paths, and build position. Never file contents.

**Tests must detect:** the serialized `next()` payload for a fixture build stays under 8 KB, and contains none of the seeded files' contents. Add a file with a distinctive marker string and assert the marker never appears in the payload.

---

### Task 6 — Cost counters

**Files:** `src/charter/loop/machine.py`, `tests/test_loop.py`

`StatusResponse` gains `passes_issued`, `passes_rejected`, `bytes_handed_over`, `distinct_connections`. Derived from the transcript and sign-offs, not separately maintained state.

**Tests must detect:** counts move with real activity — a rejection increments `passes_rejected`, two connections give `distinct_connections == 2`.

---

### Task 7 — Say what it proves, everywhere

**Files:** `src/charter/loop/machine.py`, `src/charter/skillgen.py`, `README.md`, `skills/charter/SKILL.md` (regenerated), `tests/test_plugin.py`

Rewrite `INDEPENDENCE_STATEMENT` for v2: sign-offs are proven to come from distinct server processes, each carrying its own checkable artifact — **not** verified independent reasoning. Name the three limits from design §6 (restart, adversarial agent, human clicking through). Propagate to the generated skill and README, which must explain the two-session flow and what to do when blocked.

**Tests must detect:** the existing plugin drift test already fails if the regenerated skill is not committed. Add one asserting the statement names its own limits rather than only its guarantee.

---

## Order and verification

1 → 2 → 3 → 4 gets the gate real. 5 and 6 are independent of that chain. 7 last, once the behaviour it describes exists.

After each task: full suite, then revert the task's guard and confirm its test fails. Commit per task.

**Done when:** two `Council`s with distinct ids complete a governed build; one `Council` playing both developer and reviewer is refused; a v1 record reports the check unavailable; the handover stays under budget; and the product's own description of what it proves matches what the code does.
